# IM Vuln44、45 专项自测

仅覆盖安全报告44（单聊编辑/撤回归属）、45（私钥同步/群密钥交换身份）。后端修复已合入develop，合并提交`061ec96`，修复提交分别为`5411c57`和`992e0b9`。需要发布的dev选项是`msg-srv`、`msg-job`、`group-srv`、`im-gateway`（当前dev流水线为WebSocket）。本脚本不发布服务，预期提交不能直接当作实际运行版本。

只复用既有20/22/42/43/47结果，不执行那些测试；46本轮不改。真实执行由可访问dev的云主机完成，本地fake单测不能代替真实验收。

## 准备配置

使用Python3.9以上及仓库`requirements.txt`。将必要配置放入本地忽略文件，例如`.security/im-v44-v45.env`。可以从云主机已有`.env.dev`取有效的专用账号凭证，但不要把凭证贴到聊天、终端输出或报告，不要覆盖原配置。

```dotenv
IM_SECURITY_ENV=dev
IM_SECURITY_DEPLOYMENT=<已由发布记录或负责人确认的实际部署版本>
IM_SECURITY_HTTP_BASE_URL=<dev HTTP根地址>
IM_SECURITY_WS_URL=<dev WebSocket地址>
IM_SECURITY_USER_ID=<专用A的UID>
IM_SECURITY_TOKEN=<A现有有效token>
IM_SECURITY_USER_ID2=<专用B的UID>
IM_SECURITY_TOKEN2=<B现有有效token>
IM_SECURITY_CLIENT_TYPE=2
IM_SECURITY_TIMEOUT=10
IM_SECURITY_APP_VERSION=9.9.9
IM_SECURITY_KEY_GROUP_ID=<A/B都在的专用普通群ID>
# 可选：已确认不是这个普通群成员的另一个测试账号。不填则该项明确受阻。
IM_SECURITY_KEY_NONMEMBER_UID=
```

各项部署版本可依据现有发布记录或用户明确确认；无需为自测额外申请Kubernetes/ECR权限。脚本只记录版本来源，不声称已独立核验运行镜像。不要把占位版本或计划发布的版本写成已部署。

44要求A/B互为好友、专供本次测试，并正常断开Web。45要求同一组账号在专用普通群中，且其他App/PC/Web全部正常断开，避免测试marker交给真实客户端；不要求手机App登录。普通群不能复用42超级群频道R，也不要更改R/P/Q、成员关系或已有消息。没有合适的普通群或有效token时停下报告缺项，不自动建号、恢复凭证、扫码登录、加好友、拉群或踢设备。

脚本只读设备列表作鉴权和空槽前置，不是在重测43。只对有效响应中的在线状态最多等待3秒，容纳上一个脚本连接正常关闭后的异步离线；失效token、HTTP错误立即停止，持续在线的设备也会阻断，不通过登录新端顶掉已有会话。

## 分阶段执行

以下命令在仓库根目录执行，Windows也可用`python`或虚拟环境Python解释器。先44，检查结果后再45，每次使用全新的报告目录。

```bash
python -m im_test.run_security_44_45 --env-file .security/im-v44-v45.env --suite 44 --allow-test-writes --fixtures-confirmed --report-dir .reports/im-security-v44-run1
```

```bash
python -m im_test.run_security_44_45 --env-file .security/im-v44-v45.env --suite 45 --allow-test-writes --fixtures-confirmed --report-dir .reports/im-security-v45-run1
```

`--allow-test-writes --fixtures-confirmed`授权以下已明确的专用夹具变更，不能用于其他测试。两个开关缺一时入口不会发包。入口先清除继承的`IM_*`、`DM_*`、`BI_*`和pytest附加配置，只从指定文件读取IM参数；44/45写开关仅在对应子进程开启，旧42写许可、43踢设备、47日志入口始终关闭，不修改`.env`/`.env.dev`。不要改成全目录pytest或带`--showlocals`运行。

也支持`--suite both`顺序运行；44失败或跳过时不自动继续45。每阶段`--maxfail=1`，失败后停止，不自动重试或重发。已有报告目录拒绝覆盖。接收业务ACK时会缓存异步下行，不把推送帧误当操作回应，不自动回已读或送达ACK。

## 44覆盖及夹具变化

HTTP回源观察v1、v2各8项，共16项；修改请求始终是同一WebSocket协议，不能称为两套WS版本。

- A冒用B的身份，编辑/撤回B发的消息，以及尝试编辑B的发件副本：必须收到匹配消息的明确`ERR_CHAT_FORBIDDEN`，且双方鉴权回源看到的原记录、内容和状态保持稳定。
- 本人普通编辑、本人发件副本编辑、本人撤回：必须明确成功且预期副本实际落库，其他副本按原语义保持；只收到ACK不通过。
- 普通编辑及发件副本编辑的嵌套From/To/msgId伪造：服务端必须按可信账号及原消息归一化，存储不得出现伪造身份。

每项只使用一条全新的普通未加密消息：正常`0x1001`创建收件副本，正常`0x1011`创建本人发件副本，再执行一次待测变更。最多新增16条消息及其双副本、编辑/撤回相关记录，不读取或消耗历史列表，不清理已有消息；失败可能留下部分已创建夹具。消息ID在发送前写入JUnit属性，失败后也能定位。不要回退状态、改库或把同一发送重放为“准备”。

HTTP不暴露数据库`owerId`，报告只写“分别以A/B鉴权回源确认副本”；不能声称直接查库。某些越权请求可能先在归一化后的好友检查被拒绝，真实结果不能单独证明后续每一层DAO检查都被执行。

## 45覆盖及判断边界

- 群`0x2301`：合法成员交换的marker必须真正进入目标队列，伪造发送者必须收到明确拒绝；可选非成员目标也须有合法正控及明确拒绝。实际ACK使用`GroupChatAck`，错误码是字段5。
- 群`0x2303/0x2305`：创建本轮唯一交换记录F，伪造回应后B的F保留，B本人回应后F消失并为A生成通知N；再验证伪造确认不消耗A的N，A本人确认后N消失。N使用外层新消息ID。只ACK本轮记录，旧队列逐项复核不变；读队列不携带`deliveredMsgIds`，达到500条上限时受阻，不清旧队列。
- 私钥`104/103/106`：同账号Web槽回环使用opaque marker证明合法转发，不读取或安装真实私钥。对伪造账号的请求，如果没有明确拒绝ACK，只能记为受阻；没有下行和等待超时不能证明鉴权已拒绝。
- 私钥`101`依赖App目标。没有App时即使收到App离线ACK，也不算完整同步通过。脚本不登录手机，不触发真实App取钥来凑通过。

45当前最多10项：2项群用例、4项私钥正控、4项私钥负控。当前后端静默拒绝私钥非法包，预期会有明确的“证据不足”跳过；不能把剩余跳过改成通过，也不要为此扩大到47日志扫描、Redis访问或手机测试。测试marker不是RSA/TEA密钥，不改变服务端密钥托管、加密算法或密钥版本。

## 报告和退出码

已启动的测试阶段在新报告目录生成JUnit XML及`summary.json`，记录目标、配置中的部署版本及其来源、通过/失败/错误/跳过数量。入口参数或配置文件错误会在发包前直接返回2。XML属性记录本轮新消息、交换消息和观察方式；报告不含token、真实密钥、设备标识、消息正文或原始响应。

- `0`：所有所选项全部通过。
- `1`：存在失败或错误，停止后续阶段。
- `2`：缺前置、跳过/受阻、报告缺失或结果不完整；不能宣布全部通过。

失败后先按已记录ID只读核对，交回具体阶段、ACK码、通过/失败/跳过数量和报告路径，不自动重跑。正常结束只断开连接，不注销token，不调用kick、PushTokenSync、频道已读或其他测试入口。
