# IM Vuln42、43、47 自测

这组脚本用于已经部署对应修复的 **dev 环境**。配置后由使用者执行；本次交付只跑本地 fake/协议测试，没有连接真实 dev、踢设备或发送消息。已有 Vuln20/22 用例及配置保持兼容，另见 `IM安全回归.md`。

代码基线为 `fix/im-p1-42-43-47@875b0bc`，dev 合并版本为 `7b999c2`。请填写环境**实际部署版本**；也可使用包含修复的后续版本，不能只因分支已合并就认为部署完成。多实例需确认版本一致，一次经负载均衡通过不能证明所有实例均已覆盖。

## 先配置与先跑什么

在原 `.env` 补 `.env.example` 末尾新增字段，不要覆盖原账号配置。复用：

```dotenv
IM_SECURITY_ENV=dev
IM_SECURITY_DEPLOYMENT=实际部署版本
IM_SECURITY_HTTP_BASE_URL=确认过的dev网关根地址
IM_SECURITY_USER_ID=专用账号A
IM_SECURITY_TOKEN=A本人的有效token
IM_SECURITY_USER_ID2=专用账号B
IM_SECURITY_TOKEN2=B本人的有效token
```

`IM_SECURITY_HTTP_BASE_URL` 不自动复用旧 `IM_HTTP_BASE_URL`。缺环境、版本、账号或数据时明确 **SKIP**；配置错误、401/5xx、超时、重定向、HTML 或畸形 protobuf 都不能当成修复通过。不要开启 `--showlocals`、HTTP 调试或凭证/响应转储。

优先运行只读部分：

```bash
python -m pytest im_test/tests/security/test_channel_identity.py \
  im_test/tests/security/test_device_identity.py -m 'not write' -v \
  -o junit_family=xunit1 --junitxml=.reports/im-security-v42-v43-read.xml
```

这条命令不登录、不发消息、不踢设备、不修改推送 token；V42 部分仍需下面的专用频道数据。不要用整个 `im_test/tests/` 代替上述文件范围，旧功能测试会发送消息、登录或清离线 ACK。

## Vuln42：请求体 UID 不能切换频道操作身份

这不是再次验证非成员门：需要 **A/B 都是成员**的专用安静频道 R，与 Vuln22 的“A 在、B 不在”的 P 分开，避免成员校验把 UID 漏洞遮住。

```dotenv
IM_SECURITY_IDENTITY_CHANNEL_ID=R
IM_SECURITY_IDENTITY_MESSAGE_ID=R内双方可读的固定普通广播消息ID
IM_SECURITY_IDENTITY_FIXTURE_CONFIRMED=1
IM_SECURITY_IDENTITY_ALLOW_WRITE=0
IM_SECURITY_IDENTITY_STATE_CONFIRMED=0
IM_SECURITY_IDENTITY_WRITE_VERSION=
```

脚本先用 A/B 各自凭证读取同一条固定非空普通广播，确认双方有权、token 有效、正文和 Mongo 游标一致。随后先读取 A/B 各自状态，再以 **A 的 Authorization + B 的请求体 UID** 请求，结果必须保持 A 的状态，B 前后不变。空数据或两人的状态完全相同无法区分是否修复，对应项不会算通过。

| 路由（v1/v2） | 前置与验证 | 状态影响 |
| --- | --- | --- |
| `readIndexes` | A/B 均有合法且不同的已读游标，伪造请求仍返回 A 游标 | 只读 |
| `atMessages` | A/B 均有非空且不同的定向 @ 索引，伪造请求仍返回 A 集合 | 只读 |
| `oprMessage` | 双方在 R 有非空且不同的待处理操作 | 可能初始化操作游标，必须开写许可 |
| `oprMessages` | 同上；全频道返回必须只落在可消耗的专用范围 | 会涉及账号所有频道，必须开写许可 |
| `readIndexes/edit` | 固定广播游标比双方已读游标更新；伪造请求只推进 A，不推进 B | 推进 A 游标，可能删除 A 对应范围的 @，不能自动回退 |
| `oprMessages/verify` | 双方待处理列表不同但有相同末条锚点；本人 ACK 正控后，伪造 B 的 ACK 不得消耗 B | 消耗 A 的待处理操作，不能自动恢复 |

使用专用账号，停止 A/B 的 App、PC、H5 自动拉取/ACK。对 `oprMessages`，应确认**两个账号加入的所有频道均属于本次可消耗测试范围**，不允许夹带业务频道。不能满足这些条件就保持跳过。

写状态用例按版本、按操作分开执行。确认可消耗夹具后才设置：

```dotenv
IM_SECURITY_IDENTITY_ALLOW_WRITE=1
IM_SECURITY_IDENTITY_STATE_CONFIRMED=1
IM_SECURITY_IDENTITY_WRITE_VERSION=v1
```

```bash
# 先测可能初始化游标的操作读取
python -m pytest im_test/tests/security/test_channel_identity.py \
  -k operation_reads -v -o junit_family=xunit1 \
  --junitxml=.reports/im-security-v42-v1-operations.xml

# 各自重新准备夹具后再运行这两个消耗状态的用例
python -m pytest im_test/tests/security/test_channel_identity.py \
  -k read_index_update -v -o junit_family=xunit1 \
  --junitxml=.reports/im-security-v42-v1-update.xml
python -m pytest im_test/tests/security/test_channel_identity.py \
  -k operation_ack -v -o junit_family=xunit1 \
  --junitxml=.reports/im-security-v42-v1-ack.xml
```

换成 v2 前需用新消息/@/操作重新预置可判定状态，并将 `IM_SECURITY_IDENTITY_WRITE_VERSION` 改为 v2、报告名改为 v2。另一版本明确跳过。脚本不会通过回写 Redis/Mongo 恢复已读/操作游标；即使测试失败，也可能已经推进了某一账号状态。结束后按专用数据约定重新预置或废弃 R，写许可复位为 0。

## Vuln43：设备列表和踢设备归属

只读设备列表不需要频道配置。v1/v2 分别读取 A/B 本人非空设备列表作为正控，再交换请求体 UID。伪造请求必须返回认证账号的设备指纹，不能读取另一个账号设备；前后再次读取验证状态稳定。设备标识、登录时间、设备详情只在内存比较，不输出报告。

```bash
python -m pytest im_test/tests/security/test_device_identity.py -m 'not write' -v \
  -o junit_family=xunit1 --junitxml=.reports/im-security-v43-devices.xml
```

### 踢设备：每次只运行一个阶段

踢设备**不是无害的负向请求**。修复后的 A 请求即使在 body 声明 B，服务端也可能实际踢掉 A 自己的同端设备，并撤销其登录 token。因此仅对专用 **Web 槽位（clientType=2）**执行，不测试 App 槽位，避免连带踢扫码 PC。

准备：

1. A/B 各有一个在线的专用 Web 目标设备，两个 `DEVICE_TOKEN` 分别对应它们的设备标识。
2. 基础 `IM_SECURITY_TOKEN/TOKEN2` 必须就是上述目标 Web 设备的登录凭证，不要随意换成其他客户端 token。
3. A/B 各另准备一个**不同客户端、仍然有效**的观察 token。目标 Web 被踢后，用它查询目标设备状态；观察 token 必须与该账号目标 token 不同。
4. 每个阶段前重新登录准备 A/B 的目标设备和凭证，并关闭其他会自动重连/刷新 token 的客户端。脚本不会替你登录或恢复被踢的会话。

```dotenv
IM_SECURITY_ALLOW_DEVICE_KICK=1
IM_SECURITY_DEVICE_KICK_PHASE=forged_uid
IM_SECURITY_DEVICE_KICK_VERSION=v1
IM_SECURITY_DEVICE_TOKEN=A的专用Web设备标识
IM_SECURITY_DEVICE_TOKEN2=B的专用Web设备标识
IM_SECURITY_DEVICE_OBSERVER_TOKEN=A另一个客户端的有效token
IM_SECURITY_DEVICE_OBSERVER_TOKEN2=B另一个客户端的有效token
```

```bash
python -m pytest im_test/tests/security/test_device_identity.py -m write -v \
  -o junit_family=xunit1 --junitxml=.reports/im-security-v43-kick-v1-forged.xml
```

`forged_uid` 验证 A 伪造 B 的 UID 后，B 目标设备仍存在且 B 目标 token 仍能完成本人鉴权；`own_uid` 验证本人正常踢设备仍有效。两阶段分别运行，不能在同一批目标/凭证已经被消耗后连续执行。每阶段重置后再换 v1/v2；保留四份报告，不把单阶段通过当成全覆盖。结束后恢复所需会话并将 `IM_SECURITY_ALLOW_DEVICE_KICK=0`。

### TCP/WS 推送 token 同步的覆盖边界

服务端原来已有“请求 UID 必须等于连接 UID”门禁。本次脚本提供协议/ACK 的本地验证和明确的真实补验边界，默认不改推送 token。只有错误 ACK 不能证明 token 未写入；只有成功 ACK 也不能证明同步持久化和恢复成功。

真实补验需专用账号及槽位、保留原 push/VoIP 数据：A 连接伪造 B UID 同步时应返回 `ERR_TRANSMISSION_FORBIDDEN`，且从可信存储/消费证据确认 B 未变化；本人同步应成功并确认落库；最后恢复原值并复核。未完成这些步骤时，报告应标记该入口/持久化/恢复**未验证**，不能据此宣布 Vuln43 所有入口全部通过。

## Vuln47：检查运行日志，不以 HTTP 成功代替

本套件不接 ELK、不自动触发消息或加解密。它读取**人工导出的完整 dev 日志**，自动检查环境/版本/时间/服务、必要安全诊断，以及已知测试秘密的原文和常见编码是否泄露；操作成功、输入确已到达链路、日志导出完整性由人工证据声明。

1. 使用专用测试账号、测试密钥和可识别的消息正文。完成正常登录、推送同步、消息投递/历史读取、单聊/群/频道重加密及受控错误、通话等相关操作，并保留成功结果证据。普通伪造 token 被拒绝，不能代替正常登录的凭证日志验收。
2. 对同一个部署版本和明确时间窗口导出运行服务的**全部日志**，不要按哨兵字符串先筛选或先脱敏。按实例核对导出范围；至少包含可对应到实际操作的安全诊断。
3. 把 `docs/examples/im-security-v47-manifest.example.json` 复制到本地忽略目录 `.security/`。模板故意不能直接通过，需填写真实前置与证据；不要直接在受版本控制的模板里写凭证。
4. 在 manifest 的 `sentinels` 填入这次实际使用的六类值：`login_token`、`push_token`、`voip_token`、`private_key`、`tea_key`、`plaintext`。正常登录只能使用短期专用测试账号的真实凭证；临时凭证仅放本地忽略文件，严禁提交或打印。可额外检查 ciphertext/livekit_token/public_key。
5. `services` 必须声明清单中 13 个运行制品。已运行的配 `running/file`；确未部署的可配 `not_running/reason`，报告会明确不属于完整 13 项覆盖。不能把已运行但漏导出的服务写成未运行。
6. 每个成功场景写入时间、人工结果引用、已使用的秘密类别、对应服务的安全诊断片段。每个运行服务都要有成功证据，crypto-srv 还需有受控失败场景。六类输入都要有成功正控，不能仅填几个字符串但没有实际使用。

每个服务的文件为 UTF-8 JSONL/NDJSON，一行一条。请按 ELK 实际导出字段转换，完整保留原始日志（可为字符串、对象或数组）在 `message` 中，统一元数据：

```json
{"timestamp":"2026-10-31T02:01:00Z","service":"login-srv","deployment":"实际部署版本","environment":"dev","message":"这里放完整原始日志，不要事先去掉token或正文"}
```

时间使用带时区 ISO-8601。manifest 相对文件路径以其所在目录为基准。`test_accounts_only=true` 表示专用测试数据，`export_complete=true` 表示确认日志没有按正文筛选/提前脱敏；只有完成实际准备后才能设置。未知格式、缺服务、空日志、版本不符、未覆盖输入、缺成功证据或安全诊断均失败。

```dotenv
IM_SECURITY_LOG_MANIFEST=/本机路径/sync-dm-test/.security/v47-manifest.json
```

```bash
python -m pytest im_test/tests/security/test_sensitive_logs.py -v \
  -o junit_family=xunit1 --junitxml=.reports/im-security-v47.xml
```

发现泄露时只显示服务名、行号、类别，不显示匹配值和整条日志。报告记录“人工操作与导出 + 自动本地扫描”、实际服务/日志数量、缺失服务及是否全 13 覆盖。扫描只能发现已知测试值、已覆盖的编码形式及私钥头等信号，不能证明任意未知凭证或所有请求永不泄露。通过只代表该版本、该窗口、该导出范围的已知输入检查，不能替代真实业务结果核对或全实例验收。
