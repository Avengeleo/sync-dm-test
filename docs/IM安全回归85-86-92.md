- 85：A为普通群G1的群主，B为普通成员，均为专用测试账号；G2仅供跨群项使用，A/B也都在G2。由操作人只读确认真实群主和成员关系，再给夹具确认许可。不得用超级群P/Q/R，不自动建群、加群、退群、改角色或补账户。

## 执行与结果规则

每次仅选一项；两份写许可必须在CLI显式给出，只在子进程生效。子进程清除继承的IM/DM/BI配置及PYTEST附加参数，禁止从根.env补账号；其他安全写开关全部关闭。不要直接全仓pytest。

### 85：v1、v2分阶段，新夹具自动逐项准备

```bash
python -m im_test.run_security_p2 --env-file .security/im-p2.env --suite 85 --version v1 --allow-test-writes --fixtures-confirmed
```

确认v1结果与新消息ID后，再运行v2：

```bash
python -m im_test.run_security_p2 --env-file .security/im-p2.env --suite 85 --version v2 --allow-test-writes --fixtures-confirmed
```

每个版本9项：伪造发送者撤回、跨群撤回、本人撤回、群主撤回；4种群ACK命令身份绑定；已读同步身份绑定。跨群项先在G2正常发一条正控，避免把“无G2成员资格”误认为原消息归属保护。缺G2不能算跨群通过；可用 `--case` 仅选已经准备好的阶段。

只运行一项示例：

```bash
python -m im_test.run_security_p2 --env-file .security/im-p2.env --suite 85 --version v1 --case forged_sender_cancel --allow-test-writes --fixtures-confirmed
```

ACK/已读使用两条交叉消息：A发M1，B发M2。先验证A伪造B不会改变B在M1上的状态；再用A鉴权带B的UID操作M2，确认实际推进的是A；ACK阶段最后由B本人确认M1作为正控。无需新增C或App观察token。

4种ACK使用本轮普通消息的精确记录测试共同处理器的身份绑定，不创建真实加群通知或改成员；不声明覆盖这些通知各自的生成逻辑。真实多端已读通知路由仍由后端Go回归覆盖，本套件不登录额外App/PC来声称已实测该路由。

各阶段先记录随机新消息ID，再发送一次并等待明确ACK及落库；不会因超时重发。全部18项一般共30条新普通群消息（包含两条G2正控），不自动清理或回退状态。中途失败也保存已发送ID，先核对再人工决定，不整套盲重跑。

### 86：先WS，TCP独立运行

```bash
python -m im_test.run_security_p2 --env-file .security/im-p2.env --suite 86 --transport ws --allow-test-writes --fixtures-confirmed
```

WS共5项：正常心跳正控、超限消息、分片超限、压缩展开超限、业务命令限速。每项先在同一连接得到本人成功登录ACK；不把握手失败、超时、鉴权失败或其他踢线当成保护通过。压缩未协商成功时受阻，不伪造已覆盖。

```bash
python -m im_test.run_security_p2 --env-file .security/im-p2.env --suite 86 --transport tcp --allow-test-writes --fixtures-confirmed
```

TCP共4项：正常心跳、仅4字节越界长度头、合法分片、业务命令限速。不将WS压缩项计入TCP通过数。限速最多单连接 `2*cmdLimitRate+2` 个心跳（上限1002）；没在1秒内形成超额突发则受阻，不自动提高强度或重跑。只发正常心跳，不发消息、推送同步或重复登录。

断连证据证明所配置入口会拦截，不独立证明是后端还是代理拦截；需要定位归属时结合本轮服务日志。真实登录重试限速、TCP粘包和响应/推送并发写由后端Go回归覆盖，本套件不把未跑的路径记为真实环境通过。

### 92：只读robot-srv完整日志导出

复制 `docs/examples/im-security-v92-manifest.example.json` 到 `.security/`。由负责执行的人准备正常、错误、慢查询三类受控场景及实际SQL测试参数，然后完整导出同一窗口的robot-srv日志。**本脚本没有安全的外部SQL触发入口，不连接数据库，不注入SQL、故意制造慢查询、修改日志级别或服务配置。缺场景时保留受阻。**

JSONL每行：

```json
{"environment":"dev","service":"robot-srv","timestamp":"2026-11-09T01:01:00Z","message":{"msg":"robot mysql query failed","elapsed_ms":1,"error_type":"*mysql.MySQLError"}}
```

`message`保留原始完整文本或对象，不筛选、不脱敏。可添加环境/服务/时间元数据，不重写message。expected_line_count来自日志查询的权威计数；文件SHA256由扫描器写入报告。参数最少16字符且必须实际进入对应SQL场景，不用随意字符串作为泄露探针。

manifest记录版本依据、窗口、完整性确认、实际场景引用、参数ID映射；错误/慢查询还需给出精确的1起始JSONL行号，分别匹配`robot mysql query failed`与`robot mysql slow query`。正常查询原本就不打SQL，使用调用成功结果证明实际执行。版本和场景引用属于操作人提供的证据，报告不声称脚本独立验证。

```bash
python -m im_test.run_security_p2 --env-file .security/im-p2.env --suite 92
```

只扫robot-srv及这次SQL参数，不扩大到47的全服务或其他凭据类型。检查原文、JSON转义、base64、hex及字节数组等形式；报告不输出参数值或日志原文。仅文件里“0命中”、空日志、缺错误/慢查询或导出计数不符，都不能算三项场景已验收。
